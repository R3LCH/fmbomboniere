# FM Bomboniere: applicable skills digest

Use a quiet, image-led, light pastel boutique showcase: elegant typography, a short introduction, authentic current collection photography and contact information. Smooth motion means understated transitions, not cinematic scroll hijacking. Rules below summarize read sources; `[INFERENCE]` identifies proposed project choices, not existing code or verified results.

## Per-skill applicable rules
### design-taste-frontend
- Declare the design read and reasoned dials. `[INFERENCE]` FM: refined local boutique, variance 4-5, motion 4, density 2-3, not default 8/6/4 spectacle.
- Serif is justified by the elegant heritage-adjacent brief/monogram, not generic premium labeling; avoid default Fraunces/Instrument Serif and random mixed-family emphasis.
- Hero desktop H1 <=2 lines, subtext <=20 words, CTA visible initially, <=4 text elements, top padding <=6rem; desktop nav 64-72px, max 80px.
- Grid, real imagery, consistent theme/radii, meaningful motion, visible focus/contrast and reduced motion apply.
- Exclude SaaS defaults, fake screenshots and magnetic pointers. Two explicit pastels override one-accent dogma: use both as surfaces with one interaction accent. Explicit white/pastel direction supports light-theme lock rather than unsolicited dark mode.
### high-end-visual-design
- Apply generous whitespace, purposeful type, optical alignment, custom easing and explicit mobile collapse below 768px.
- Animate transform/opacity; use will-change sparingly, reserve backdrop blur for fixed chrome, document layer roles.
- Reject harsh shadows, thick mixed icons and generic equal feature-card rows.
- Exclude mandatory double bezels/squircles, floating glass nav, button-in-button arrows, pills on every heading, magnetic hover and 800ms blurred 64px reveals: wrong personality for this brief.
### minimalist-ui
- Favor open flat editorial layouts, charcoal text, washed-out pastels and nearly absent shadows; no neon or stacked glass.
- Serif display plus restrained sans UI/body; body leading ~1.6, headings ~1.1; no decorative mono metadata.
- Quiet reveal baseline: opacity + translateY(12px), 600ms, cubic-bezier(0.16,1,0.3,1); short stagger, active scale 0.98.
- Exclude workspace bento, fake OS chrome, grain/tints on merchandise and looping blobs. Its optional radial backgrounds contradict its gradient ban; choose the ban here.
### apple-design
- Immediate press feedback; do not lock input during transitions; reversible interaction starts from current visual state.
- Use size-specific tracking, optical sizing, rem/em layout scaling, comfortable body leading and enlarged-text/reduced-motion support.
- If approved gesture UI exists, use pointer capture, grab offset, velocity handoff and soft bounds; no-bounce spring by default, bounce only after momentum.
- Exclude wholesale Apple glass styling, haptics/audio and custom gesture infrastructure for a simple gallery; native scrolling suffices.
### redesign-existing-projects
- If an existing FM implementation exists, audit stack/brand/IA/links/states and evolve it, not migrate frameworks.
- Prioritize type, palette, spacing and hover/press/focus; preserve working behavior and identity.
- Semantic landmarks, skip link, image alt, favicon, title/description/OG and real destinations apply.
- Existing-site migration rules are conditional, not greenfield facts. Reject fabricated realistic metrics/reviews/dates, aggressive overlap and inertial scrolling.
### gpt-taste
- Borrow AIDA lightly: hero → short explanation → collections → contact, without adding unnecessary sections.
- Short naturally wrapped H1, readable CTAs, generous rhythm and complete image-grid composition apply.
- GSAP motion must actually work with cleanup, not merely be claimed.
- Exclude mock Python execution, mandatory two advanced paradigms, pinning/scrubbing, 0.8 image growth, darkened products, inline image words and marquees. Never fabricate tool execution; gallery gutters are intentional, not empty bento cells.
### stitch-design-taste (+ DESIGN.md)
- If Stitch is used, document atmosphere, named functional hex colors, type/radius/spacing, responsiveness and exact code-phase motion in project DESIGN.md.
- Fluid type, Grid, max-width, >=44px targets, honest states and no horizontal overflow apply.
- Supplied DESIGN.md is an example, not FM tokens; electric accents, 2.5rem cards and high dials do not transfer automatically.
- Exclude mandatory inline-photo titles, perpetual loops, dashboard components, spring-only motion and Fraunces/Instrument Serif defaults. Stitch static screens do not prove implemented animation.
### image-to-code
- When image generation is available for the visual build, generate readable standalone section references before coding, then analyze them; regenerate unclear detail instead of cropping tiny boards.
- Extract layout, copy, type relationships, spacing, CTA/radii, palette and media ratios; preserve them through implementation.
- Open gallery-led cadence, stable media frames, no nested boxes/micro-label clutter or overfilled first viewport apply.
- Exclude mandatory four signature components, spectacle cues and generic pricing/testimonial packs. Generated products/copy are not evidence of current inventory and cannot override verified content.
### system-feedback
- Design only reachable transitions; menu open/close is self-evident, image pending/loaded/failed may need local status.
- Keep feedback at the affected region; distinguish loading/failure, preserve usable content, no fake progress/success.
- External WhatsApp/mail/map links cannot claim a message was sent; a form requires real delivery and truthful failure behavior.
- Exclude optimistic saves/background systems unless they exist; no ritual spinners/toasts on a static page.
### edge-hunt
- After scope is selected, define contract plus preserved invariant: closing product preview preserves gallery position and restores focus.
- Use real axes: input/device, viewport/text size, image loading and action order; prioritize 5-10 meaningful intersections.
- Proposed checks: rapid open-close-open, failed large image, Escape/focus return, touch rotation with overlay open, reduced motion with reveal, narrow viewport with enlarged Italian text.
- Exclude payments/permissions/sync/concurrency with no matching features. Proposed scenarios are not observed defects; test pixels/focus, not merely API output.
### nodumb
- Before broad redesign, state customer result, cheapest sufficient solution, applicable facts, boundaries and observable success.
- Reuse existing stack/patterns; inspect dependencies before import; no speculative CMS/design-system architecture.
- After failed verification/repeated symptoms obtain a new fact on the broken layer before another edit; do not reconfirm user-reported failures.
- Exclude architecture ceremony for agreed mechanical changes and unrequested checkout/integrations/telemetry.
### nodumb-loop
- Route to earliest unresolved layer: purpose → ask-nodumb; method/scope → nodumb; contract edges → edge-hunt; uncertainty → system-feedback.
- Invoke only a skill capable of changing the next step; return to the affected layer, not a compulsory pipeline.
- Apply changelog-discipline after qualifying completed code changes. This research-only digest does not warrant a repository changelog edit.
### ask-nodumb
- Separate experience, model and technology: refined showcase; curated collections/contact; stack precedent is implementation, not customer need.
- Recommend simple gallery/contact given the clear brief; ask only consequential human-choice questions not answerable from artifacts.
- Define a small semantic color/type/spacing/motion vocabulary from repeated actual usage, not future-proof abstraction.
### changelog-discipline
- Record each completed coherent code change in [Unreleased] Added/Changed/Fixed when maintaining/setting up changelog; not each file/commit.
- Non-obvious decisions include what/where/why/before/rejected alternatives; mechanical entries say behavior unchanged only when supported.
- Current values/contracts belong in code/docs, not changelog. Release summary has what/where/why/before; this is not a PR/commit/user-release-note template.
### full-output-enforcement
- Deliver every requested component/section end-to-end; no stubs, mock delivery, omitted middle, TODO placeholders or “continue the pattern.”
- Complete digest means all 18 skills plus merged rules, not unnecessary length.
- Pause/continue instructions do not override this assignment's complete terminal handoff.
### brandkit
- Preserve supplied FM logo consistently; derive coherence from celebration/personal care/gifting rather than invent a replacement mark.
- Borrow sparse readable type, strong negative space, repeating palette and art-directed product/material imagery.
- If a board is requested later, use relevant stationery/packaging/web applications with clean gutters, not arbitrary devices/fake tiny UI.
- Exclude logo regeneration, site-wide charcoal deck style, developer/security/gaming/brutalist cues, CRT/halftone/crosshairs/terminal chrome. Existing logo sparkles do not justify sparkles across the website.
### emil-design-eng
- Every motion needs purpose/frequency rationale; short UI timing, responsive press feedback, no keyboard action delays or input lockouts.
- Custom ease-out for entry/exit, ease-in-out for spatial morphing; transitions for retargeted UI, springs for gestures; no scale(0).
- Fine-pointer-only hover, reduced-motion opacity/color feedback, stagger 30-80ms without blocking interaction.
- UI code reviews require a Before | After | Why table. Exclude decorative 3D/mouse tracking/hold-to-delete/tooltip infrastructure when absent.
### improve-animations
- Read-only advisor: map actual libraries/tokens/personality, audit purpose/timing/origin/interruption/performance/a11y/cohesion and cite observed path:line evidence.
- Prioritize high-leverage findings, separate defects from opportunities, respect deliberate tradeoffs; code alone cannot prove motion feel.
- Plans need exact target values/current excerpts/conventions/boundaries/done conditions plus slow-motion, reduced-motion and device feel checks.
- No source audit/plans/commit stamping requested here: this ticket is a skills digest, not implementation.

## Merged quality checklist
- [ ] Brief wins: white/blue/pink, refined not futuristic, brief service copy, current collections, clear contact. No unrequested ecommerce/CMS/forms/prices/testimonials or invented business facts.
- [ ] `[INFERENCE]` Starting tokens: canvas #FFFFFF; blue surface #E1F3FE; pink surface #FDEBEC; ink #2F3437; body #55545A; action/focus #7B4656. Pastels are surfaces, not pale text. Retain logo colors without site-wide glitter/gold. Measure contrast rather than assume it.
- [ ] `[INFERENCE]` Self-host licensed Cormorant Garamond display + Outfit body/UI WOFF2 with font-display:swap. Availability/licenses not checked. Display clamp(2.25rem,5vw,4rem), line-height >=1.1, tracking -0.02em; body 1rem-1.125rem/1.6, near-zero tracking, <=65ch. Reserve italic-descender clearance.
- [ ] `[INFERENCE]` Container 1200-1400px, gutters 1rem mobile/2rem tablet/3-4rem desktop; section spacing clamp(3rem,8vw,6rem); grid gaps 1-2rem. Hero padding <=6rem; rem/Grid, not flex percentage hacks or forced 100vh.
- [ ] One radius rule and locked light theme; spacing instead of unnecessary cards. No triple nesting, giant pills, equal three-feature cards, repetitive zigzags, gratuitous glass/bezels/shadows or eyebrows everywhere.
- [ ] Motion tokens: reveal cubic-bezier(0.16,1,0.3,1); UI out cubic-bezier(0.23,1,0.32,1); spatial morph cubic-bezier(0.77,0,0.175,1); drawer cubic-bezier(0.32,0.72,0,1). Choose by purpose.
- [ ] Reveal baseline 12px+opacity/600ms/once; stagger 30-80ms (60ms proposed). Press scale 0.97-0.98/100-160ms; small popover 125-200ms; menu 150-250ms; simple overlay 200-300ms. Marketing 600ms is not button timing. Optional momentum spring bounce 0.2/duration 0.4, otherwise bounce 0.
- [ ] Animate transform/opacity with explicit properties. No transition:all, scale(0), UI ease-in, delayed response, infinite floats/pulses/marquees, scroll hijacks, React state per scroll frame or global manual scroll listeners. Clean up GSAP context/matchMedia/observers; do not add Motion merely to duplicate existing GSAP/CSS.
- [ ] Reduced motion: static content or <=200ms opacity, no translation/parallax/spring/loop; disable smooth anchor scrolling. Hover motion only under (hover:hover) and (pointer:fine). Failed motion/JS initialization must not hide content.
- [ ] Authentic current product imagery with source/date/permission provenance. Generated references are not stock evidence. No delivered Picsum/random stock, fake credits, misleading labels, heavy desaturation/tints changing product colors, stretched images or decorative photo-overlay labels.
- [ ] Stable width/height or aspect-ratio, intentional object-fit/object-position, responsive srcset/sizes and optimized local WebP/AVIF when feasible. Prioritize hero/LCP image, lazy-load below fold, preserve image geometry while pending/failed.
- [ ] Semantic nav/main/sections/footer, one H1, useful headings, Italian lang, skip link, descriptive product alt (alt="" only genuinely decorative), visible focus, native buttons/links, named icon controls, >=44px targets, no hover-only functions. Modal keyboard Escape/focus restore if present; no keyboard animation delay.
- [ ] WCAG AA >=4.5:1 normal text and >=3:1 large text; control/focus non-text contrast >=3:1 where required. Color is not sole state cue. Check enlarged text/reflow/high contrast; solid fallback for any translucent chrome.
- [ ] No AI clichés, scroll cues, section numbers, decorative status dots, emojis, fake metrics/people/reviews, ornamental city/time strips or visible em/en-dash separators. Actual Scalea contact address is useful, not banned decoration. Read every Italian string; desktop CTAs stay on one line.
- [ ] Current DESIGN/README docs explain tokens, motion/reduced-motion behavior, asset/source provenance and collection replacement. Permanent completed code work updates docs/changelog with rationale; research alone does not mutate repository docs.
- [ ] Main agent verifies once after all edits land, using actual available package scripts; do not invent commands or report unrun checks. This research ran no builds/tests/browser checks.
- [ ] Main-agent visual checks: 375/390/768/1024/1440px and short laptop height; no overflow; 200% text zoom/reflow; keyboard cycles, rapid reversal, failed image, actual touch, reduced-motion/contrast preferences. Slow-motion/frame-by-frame feel checks; Lighthouse/CWV targets LCP<2.5s, INP<200ms, CLS<0.1 are goals, not measurements.
